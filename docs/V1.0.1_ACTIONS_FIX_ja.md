# v1.0.0 Actions failure and v1.0.1 correction

The failed v1.0.0 run was caused by release-manifest byte hashes generated before
Git normalized CSV line endings from CRLF to LF. An ignored `*.log` file was also
listed in the old manifest.

Do not simply rerun the v1.0.0 job; the old tag points to the same faulty commit.

Recommended SourceTree procedure:

1. Pull `main`.
2. Copy the contents of the v1.0.1 repository package over the working copy,
   preserving the hidden `.git` directory.
3. In SourceTree, stage all changes.
4. Commit: `Fix Git-normalized release manifest for v1.0.1`.
5. Push `main`.
6. Select the new commit and create annotated tag `v1.0.1`.
7. Push the tag (`Push all tags`).
8. Confirm the `v1.0.1` GitHub Actions run succeeds.
9. Create GitHub Release `v1.0.1` and attach
   `elemental-feature-bank-v1.0.1-data.zip`.
10. Upload the exact same data ZIP to Zenodo.

No scientific data value changes between v1.0.0 and v1.0.1.

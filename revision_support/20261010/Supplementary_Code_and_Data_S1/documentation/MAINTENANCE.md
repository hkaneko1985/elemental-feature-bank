# Maintenance and versioning policy

Maintainer: Hiromasa Kaneko, Meiji University.
Reports and proposals: https://github.com/hkaneko1985/elemental-feature-bank/issues

Maintenance is event-driven. Triggers include reported errors, upstream changes
to data/definitions, incompatible dependencies and changes in rights evidence.
Before release, affected source versions, units, reference states, derivations
and rights are rechecked; value/coverage/Tier differences and relevant tests are
recorded. CHANGELOG and release notes describe additions, removals, corrections
and unresolved limitations.

The cited v1.0.1 remains a fixed reference. Upstream packages are not silently
updated inside it. Material changes receive a new tag and archival version.
Continuous currentness or indefinite maintenance is not guaranteed. If maintenance
ends, the fixed archive and available provenance/reconstruction records remain.

The new revision supplement is additive. Publishing it must not rewrite the
v1.0.1 release tag or substitute altered files at the cited DOI.
